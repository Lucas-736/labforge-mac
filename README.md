# LabForge（研铸）

> **Track your lab hours, hold your streak, and let 365 days of effort speak for you.**
> 记录实验室打卡与研究时长，用 365 天可视化进度与学术仪式感，为科研续航。

**LabForge** is a pure native macOS desktop & menu bar app — **SwiftUI + AppKit**, built with **Swift Package Manager (Swift 6)**. No Xcode project, no `.xcworkspace`, no `xcodebuild`. Everything works with plain `swift build -c release` under Apple Command Line Tools, on Apple Silicon and Intel alike.

---

## Highlights ✦

- **菜单栏实时打卡 (MenuBarExtra)** — a live monospaced timer in the menu bar; one click starts or ends a lab session, with the elapsed time always computed from `startTime` (sleep-resilient, zero drift).
- **Claude Editorial Design System** — the entire UI strictly follows [`DESIGN.md`](./DESIGN.md): the warm cream canvas (`#FAF9F5`) with terracotta coral CTAs (`#CC785C`), serif display headlines, hairline borders and color-block elevation — switchable in one click to the **Warm Charcoal** dark mode (`#181715`).
- **365 天陶土热图 (terracotta heatmap)** — a year-long research heatmap in the coral→cream palette, with streak and monthly rollups.
- **5 个科研段位 & 9 枚成就徽章** — Research ranks (from Novice to Legend) and achievement badges that reward first sparks, streaks, early mornings and the eight-hour day.
- **SwiftUI Canvas 暖色火花动画** — a lightweight Canvas-based spark celebration for check-in moments: warm, whisper-subtle, no neon.
- **杂志风每日报告卡 (ImageRenderer @2x PNG)** — an editorial daily report card rendered at 2× and exported as a shareable PNG.
- **手动补录 & 历史编辑 (manual backfill & history editing)** — fix or backfill past sessions; sessions crossing midnight are attributed accurately to each calendar day.
- **本地优先 (local-first) JSON 备份/恢复** — all records live in a single human-readable JSON file; import/export for backup, no account, no network.

## Architecture 🏛

Pure SwiftPM — zero Xcode dependency:

```
Package.swift (swift-tools-version: 6.0, platforms: [.macOS(.v14)])
├── LabForgeCore          — pure Foundation domain layer: Sendable models,
│                           engines (streak / rank / badge / heatmap / quotes),
│                           and JSON persistence.
├── LabForge              — SwiftUI + AppKit app: Window + MenuBarExtra,
│                           Claude Design System, Canvas spark animation,
│                           ImageRenderer report card, notifications.
└── LabForgeCoreTests     — unit tests for every core engine (swift test).
```

The core target is deliberately free of UI so it stays fast to test; the app target consumes it and owns all `@MainActor` state.

## Requirements 📋

- **macOS 14.0+** (Apple Silicon & Intel)
- **Swift 6 Command Line Tools** (or Xcode's toolchain) — `xcode-select -p`
- That's it. No Xcode project file is ever created or needed.

## Build, Test, Package & Install 🛠

```bash
# Unit tests (full Xcode toolchain)
swift test

# Unit tests under Command Line Tools only (CLT ships Testing.framework
# outside the default search paths — pass it explicitly, else zero tests run):
swift test -Xswiftc -F -Xswiftc /Library/Developer/CommandLineTools/Library/Developer/Frameworks

# Release build (pure SwiftPM)
swift build -c release
```

**One-shot build & package** (tests → release build → `.icns` → `dist/LabForge.app` → ad-hoc sign → `dist/LabForge.dmg`):

```bash
./scripts/build-app.sh                 # build + package (runs tests first)
./scripts/build-app.sh --install       # …and install to /Applications/LabForge.app
./scripts/build-app.sh --skip-tests    # skip the unit-test stage
./scripts/build-app.sh --version 1.0.0 --build-number 1
```

The pipeline packages the architecture of the machine running SwiftPM.

Artifacts land in `dist/`:

| Artifact | Description |
|---|---|
| `dist/LabForge.app` | Ad-hoc signed app bundle (`com.labforge.app`) |
| `dist/LabForge.dmg` | Installable disk image |
| `dist/AppIcon.icns` | The 研铸 icon, generated by `scripts/generate-icon.swift` |

> **Note on the CLT Swift Testing command**: `swift test` under a Command Line Tools-only machine silently runs **zero** tests unless `Testing.framework` is passed via `-Xswiftc -F -Xswiftc …`. The linker flags in [`Package.swift`](./Package.swift) cover the test target, but SwiftPM's auto-generated test runner does not inherit them, so the command-line flag above (also built into `scripts/build-app.sh`) is mandatory on CLT-only machines.

## Data & Privacy 🔒

- **Storage path:** `~/Library/Application Support/LabForge/records.json`
- Everything is stored **locally on your Mac** — no accounts, no telemetry, no network calls.
- Export a JSON backup from Settings. Restore with Merge to keep local settings, or Overwrite to replace the records and settings. The macOS login item is managed separately on each Mac.
- Writes are atomic (`Data.write(to:options:.atomic)`) to protect against corruption.

## CI — Automated `.dmg` Build ☁️

[`.github/workflows/build-macos.yml`](./.github/workflows/build-macos.yml) runs on `macos-15` for pushes/PRs to `main` and `v*` tags:

1. `actions/checkout@v4`
2. Environment dump (`swift --version`, `sw_vers`, `uname -m`)
3. `./scripts/build-app.sh` — unit tests with a non-zero "tests actually ran" assertion, release build, `.icns` generation, bundle + ad-hoc signing, `dist/LabForge.dmg`
4. Zips the app (`dist/LabForge-app.zip`) and uploads both artifacts via `actions/upload-artifact@v4`
5. On `v*` tags, attaches `dist/LabForge.dmg` + `dist/LabForge-app.zip` to the GitHub Release (`softprops/action-gh-release@v2`)
